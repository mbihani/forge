**Proposed mutation for round 7:** one `write_agent` action that rewrites `agents/savesage_agent.py` to cut latency.

**Why:** gated accuracy is close to its ceiling. Round 4 reached 0.9864. Round 6 lost only about one row's worth of transactions and one extra card-name miss. The fields still failing (network 0.0, card limits about 0.73) failed the same way in native-PDF mode too, so they look like ground-truth conventions rather than reading errors. Latency is the objective with room: it has to drop below about 12.7s with accuracy at or above about 0.9795. Luna's text pass alone has a median of about 12.9s, and round 6's page-1 identity pass lands in roughly the same window. Both calls on the critical path have to get faster.

**What the module changes:**
- **Main pass:** GLM 5.3 Flash in text mode at low effort replaces Luna text. The model hasn't been evaluated yet. Card name, network and limits still come from the Luna identity pass, which covers the card-art fields text mode can't read.
- **Identity pass:** the same page-1, no-transactions Luna call as round 6, sent twice at once; the first usable result wins. Luna's slow tail is wide (p90 is about 2× the median), so taking the faster of two should shorten the identity wait.
- **Identity deadline:** the agent now waits until whichever is later: 6s after the main pass returns, or 13s from the start. A fast GLM pass won't cut off identity results that arrive at round 6's usual timing.
- **Fallbacks:** if GLM fails or returns no summary blocks or no transactions, the agent runs Luna text (low effort), then the native-PDF chain. A GLM failure costs that row latency, not accuracy.

**Predicted result:** median latency about 10–12s, gated accuracy about 0.980–0.985.

**Risks:**
- GLM's quality on ICICI text, such as the backtick rupee sign, is unknown. If it's poor, the gate reverts the round, and we'll know whether GLM is usable.
- If GLM rejects the `reasoning_effort` setting, every row goes through the slower fallback chain and the round reverts on latency.
- Three concurrent calls per row could queue at the endpoint.
